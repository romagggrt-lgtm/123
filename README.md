# shah — Paper 1.21.11 / Java 21

**Статус: собранная реализация для дальнейшей игровой проверки, не проверенный production-релиз.**
`dist/Shahed_1.03.jar` — прежний плагин Shahed без изменений. `dist/Z_Verity_1.0.1.jar` — отдельный плагин Z_Verity. `dist/Z_Server_Pack_1.04.zip` — общий ресурс-пак формата 75: текстуры Shahed сохранены, добавлены только ресурсы Verity.
Три указанных в ТЗ JAR-файла в среду не поступили. Их ресурсы не использованы, лицензии не проверены.
В пак включена **собственная временная объёмная модель**, а не конвертация Skyfront. Для выбора и адаптации исходной модели нужны файлы и разрешающая лицензия.

## Установка

1. Используйте Paper **1.21.11**, Java **21**. Сначала сделайте копию тестового мира: взрывы по умолчанию разрушают блоки.
2. Остановите сервер и скопируйте `dist/Z_Verity_1.0.1.jar` в `plugins/`, удалив старый `Z_Verity_1.0.0.jar`, затем запустите сервер. Уже установленный Shahed не заменяйте: этот релиз его код и JAR не меняет. Не используйте `/reload`.
3. Параметры появятся в `plugins/Shahed/config.yml`. Меняйте их при остановленном сервере и перезапускайте сервер.
4. Подключите ресурс-пак, примите его в клиенте Minecraft 1.21.11. Forge, Fabric, GeckoLib и клиентские моды не требуются.

### Ресурс-пак через server.properties

В текущей конфигурации уже указан прямой URL GitHub Raw. Важно: используйте именно `raw.githubusercontent.com`, без `?download=1`. Ссылка GitHub вида `/blob/` или `/raw/?download=1` отдаёт HTML-страницу, а клиент Minecraft принимает её как маленький файл (например, 383 Б) и зацикливает загрузку.

```properties
resource-pack=https://raw.githubusercontent.com/romagggrt-lgtm/123/main/dist/Z_Server_Pack_1.04.zip
resource-pack-sha1=6e32b7a30c97cb95eb503be2d973652203b3d718
require-resource-pack=false
resource-pack-prompt={"text":"Модели и звук плагина shah"}
```

После изменений перезапустите сервер. При замене ZIP обновите SHA-1 из `dist/Z_Server_Pack_1.04.zip.sha1`. Можно поставить `require-resource-pack=true`, чтобы игроки не входили без ресурсов.
Плагин не размещает ZIP в интернете и не меняет `server.properties` автоматически. Если другой плагин управляет серверными паками, подключите этот пак через него. Предупреждение в action bar показывает, что сервер ещё не получил статус успешной загрузки пака; оно не может проверить содержимое чужого пака.

Перед запуском сервера проверьте ссылку с любой машины:

```sh
curl -fL -o /tmp/Z_Server_Pack_1.04.zip \
  https://raw.githubusercontent.com/romagggrt-lgtm/123/main/dist/Z_Server_Pack_1.04.zip
file /tmp/Z_Server_Pack_1.04.zip
sha1sum /tmp/Z_Server_Pack_1.04.zip
```

`file` должен показать ZIP, размер должен быть около 38 KB, а SHA-1 — `6e32b7a30c97cb95eb503be2d973652203b3d718`. Если сервер уже запущен со старым URL или старым хешем, удалите сохранённый ресурс-пак в `.minecraft/server-resource-packs` и подключитесь заново.

## Команды и использование

```text
/give Steve shahed
/give Steve shahed 5
/give Steve Shahed_3k
/give Steve Shahed_3k 2
/shahed give Steve shahed 5
/shahed give Steve Shahed_3k 2
```

Нужен точный ник онлайн-игрока. Количество 1–2304. Выдача по умолчанию только OP и консоли; обычные игроки используют выданные предметы. При полном инвентаре остаток выпадает у получателя.
Обработчик перехватывает только `/give` с двумя специальными идентификаторами. Остальные аргументы передаются существующей команде сервера. `/minecraft:give` и `/essentials:give` остаются нетронутыми. Если другой плагин перехватывает команды раньше, используйте `/shahed give` или `/shah:shahed give`. Интеграция с EssentialsX ещё не проверена на сервере.

### Z_Verity

Скопируйте `dist/Z_Verity_1.0.1.jar` в `plugins/` рядом с Shahed и перезапустите сервер. Выдача доступна оператору или консоли:

```text
/give Steve verity
/give Steve verity 3
/zverity give Steve 3
```

ПКМ яйцом по свободному месту ставит коробку. ПКМ по коробке выпускает жёлтый шар Verity и проигрывает звук из предоставленного `1023.MP3`. Первое ПКМ по шару пишет `Hello!`, после чего шар следует за игроком. Следующее ПКМ или удар игрока запускает сообщение от его имени, выбрасывает инвентарь в точке смерти и убивает нажавшего игрока. Пак содержит самостоятельную серверную объёмную модель шара; Forge-мод и клиентские моды не нужны.

Яйцо: ПКМ по блоку основной рукой. Нужен свободный объём вокруг точки появления. Яйцо расходуется вне Creative. Моб поднимается и переходит к горизонтальному полёту; при атаке игроком детонирует. Служебный Slime невидим, без AI и исходящего урона; отображение — ItemDisplay.

Шахед 3000: удерживайте ПКМ основной рукой минимум 25 тиков, отпустите. Предмет использует компонент `consumable` с анимацией BOW и Paper-событие отпускания, без стрел и настоящей физики лука. Защита от раннего отпускания, смены слота/руки, смерти, выхода, повторного выстрела и кулдаун реализованы. Практическая проверка клиентского удержания ещё требуется.

Снаряд движется прямым вектором, проверяет блоки и игроков трассировкой каждого тика, выбирает ближайшее попадание, не поражает стрелка напрямую своей траекторией. Сам взрыв может повредить стрелку. На границе незагруженных чанков и по достижении дальности исчезает без взрыва.

## Настройки

Полный пример: `src/main/resources/config.yml`. Все перечисленные параметры считываются реализацией. Числа ограничиваются безопасными диапазонами; NaN/Infinity заменяются значением по умолчанию.

- Естественный спавн: только NORMAL-миры из списка, интервал на каждый мир, вероятность, лимит естественных мобов. Расстояние до ближайшего игрока измеряется горизонтально. Выбираются только уже загруженные чанки; при нехватке безопасных точек попытка пропускается.
- Высота над самым высоким блоком, скорость, коррекция курса, обход препятствий, сглаживание, срок жизни и длительность взлёта настраиваются. В сложных препятствиях моб может безопасно удалиться. Длительный маршрут не прокладывается.
- Звук — самостоятельно синтезированное низкое гудение, ослабление по расстоянию и в конце жизни. Отдельные звуковые события для каждого слота полёта предотвращают взаимную остановку двигателей.
- `damage-entities` управляет уроном взрыва независимо от `break-blocks`. Нативные Bukkit-события взрыва и урона сохраняются; отмена события защиты не снимается. Учитываются также игровые правила мира. Не обещается совместимость с произвольным плагином защиты без проверки его настроек и событий.
- `unlimited-ammo: false` расходует один launcher вне Creative при успешном запуске. При `true` ничего не расходуется.
- `give-op-only: false` разрешает выдачу по permission `shah.give`; `console-give: false` запрещает консольную выдачу.
- `resource-pack.enabled` управляет предупреждениями плагина, `prompt-on-join` — предупреждением при входе. Сам пак распространяется настройками сервера выше.
- Дополнительный `limits.max-total` ограничивает суммарное число полётов (по умолчанию 128); `despawn-player-distance` удаляет мирных мобов без близких игроков.

## Сборка из исходников

На обычной машине нужны JDK 21, Maven 3.9+, Python 3 и FFmpeg с Vorbis:

```sh
mvn package
bash tools/check_math.sh
python3 tools/build_pack.py
python3 tools/check_pack.py
```

JAR: `target/Shahed_1.03.jar`, `verity/target/Z_Verity_1.0.1.jar`. Ресурс-пак: `dist/Z_Server_Pack_1.04.zip`.
В этой облачной среде воспроизводимый полный цикл: `bash tools/bootstrap-env.sh`, затем `bash tools/build.sh`. Скрипт поддерживает HTTPS-прокси и системное хранилище доверенных сертификатов, не отключает TLS и удаляет временные настройки прокси после сборки. На другой машине можно задать `SHAH_MAVEN_CACHE`.

Сборка Maven сама по себе **не запускает** `FlightMathChecks`: они запускаются отдельно `check_math.sh` и включены в `build.sh`. Отчёт с границами проверки: `TESTING.md`.

Для следующего этапа нужны доступ к официальной загрузке Paper, тестовый клиент и три исходных JAR для лицензионной проверки. Вращение пропеллера пока не реализовано. Субъективные требования к плавности, видимости, положению в руке и громкости ещё не подтверждены.
