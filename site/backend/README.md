# Подключение профиля и чата

Профиль и общий чат требуют отдельной облачной базы: существующая ссылка на статический HTML сама по себе не хранит пользователей. Для работы нужен бесплатный проект Supabase. Владельцу проекта доступны все данные; используйте только свой проект.

1. Создайте проект на https://supabase.com/dashboard. В **SQL Editor** выполните полностью файл `schema.sql`. Пароли в сам файл не вписывайте.
2. Там же выполните `select zs_private.create_owner('НОВЫЙ_ЛИЧНЫЙ_ПАРОЛЬ');`, заменив пароль на свой и не показывая его никому. Это создаст зарезервированного владельца `sqrxxx` с ролью «Владелец». Команда выполняется единожды. Пароль нельзя записывать в GitHub, конфигурацию сайта или чат. Указанный ранее в переписке пароль уже раскрыт, поэтому рекомендуем выбрать новый.
3. Для физического удаления старых сообщений в полночь по московскому времени выполните `cron.sql` (в проекте должно быть доступно расширение pg_cron). Даже без планировщика вчерашние сообщения скрываются и удаляются при следующем открытии или отправке чата.
4. В **Project Settings → API** скопируйте Project URL и публичный **anon** key (legacy JWT). Укажите их в `community-config.js`. Значения публичные; **service_role, secret keys и пароли туда вставлять нельзя**.
5. Разместите обновлённые файлы сайта. При регистрации пользователь указывает игровой ник, но сайт сам по себе не проверяет владение аккаунтом Minecraft и не выдаёт доступ на сервер. Это можно реализовать отдельно с привязкой к серверу.

Без почты нет автоматического восстановления пароля; перед реальным использованием нужно продумать управляемое восстановление. Сеансы действуют 30 дней. Ник проверяется без учёта регистра, владелец резервируется на стороне базы. Сообщения хранятся до полуночи по Москве. Клиент видит до 100 последних сообщений за день.

Ограничения: проект тестировался на локальном PostgreSQL; настройки сетевой защиты и квоты бесплатного плана зависят от выбранного проекта. Прежде чем принимать много пользователей, настройте ограничения обращений к API на стороне сервиса; базовый лимит чата и ограничение попыток входа по нику уже предусмотрены.
