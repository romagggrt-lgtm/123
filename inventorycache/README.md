# InventoryCache 1.0.1

Исправленная сборка присланного `InventoryCache.jar` для **Paper 1.21.11 / Java 21**.
Исходники восстановлены из предоставленного JAR и пересобраны против настоящего
Paper API этой версии. Команды, права и формат сохранённых наборов сохранены.

## Причина ошибки

В оригинальном классе вызов имел дескриптор
`PlayerCommandSendEvent.getCommands(): java.util.Set`. В реальном Paper API метод
возвращает `java.util.Collection`. Поэтому при отправке дерева команд обычному
игроку возникал `NoSuchMethodError`; в журнале таких исключений 26.

Новая сборка использует правильные дескрипторы `getCommands(): Collection` и
`Collection.removeIf`. Это исправление связи с API, без перехвата или скрытия исключения.
Тест изолированно загружает исходный класс из приложенного JAR, воспроизводит его
ошибку и проверяет работу исправленного обработчика с обычным `ArrayList`.

## Установка

1. Остановите сервер и сохраните резервную копию `plugins/InventoryCache/`.
2. Замените старый `InventoryCache.jar` на **один** `InventoryCache_1.0.1.jar`
   в `plugins/`. Папку данных с `kits/` и `backups/` сохраните.
3. Запустите сервер. Изменять РП и другие плагины не требуется.

## Команды

- `/dk save название [игрок]` — сохранить инвентарь указанного игрока или свой.
- `/dk load название [игрок]` — загрузить сохранённый набор, предварительно создав
  резервную копию текущего инвентаря получателя.

Как в присланной версии, команды доступны игрокам-операторам; `/dk` скрывается
из списка команд и справки у обычных игроков. Имена: 1–48 символов `a-z`, `0-9`,
`_`, `-`, без учёта регистра при вводе. Консоль эти команды не выполняет.

Наборы находятся в `plugins/InventoryCache/kits/`, резервные копии — в `backups/`.
Сохраняются основное хранилище, броня, дополнительные слоты, выбранный слот панели
и бинарные компоненты предметов Paper. Формат YAML `schema: 1` и SHA-256 прежние.
Перед заменой инвентаря проверяются данные и отсутствие изменений у получателя
за время фонового чтения/создания резервной копии. При изменении загрузка отменяется.

Дисковые операции сохранения и чтения выполняются исходным фоновым исполнителем.
Работа с инвентарём Bukkit выполняется в главном потоке. Сборка без обязательных
сторонних зависимостей, кроме самого Paper.

## Проверка и сборка

10 тестов прошли без ошибок и пропусков: воспроизведение старого ABI-сбоя,
списки команд для OP/обычных игроков, право выполнения и видимость справки,
сохранение/загрузка с резервной копией, все секции инвентаря и метаданные, совместимость
schema 1, контрольная сумма, недопустимые имена и копирование массивов.
Это проверки MockBukkit и реальных файлов; настоящий Paper-сервер здесь не запускался.

Из каталога `inventorycache/` на Java 21: `mvn verify`.
Результат: `target/InventoryCache.jar`.
