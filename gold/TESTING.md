# Проверка Z_Gold 1.0.2

Проверено 25 октября 2026 года. Сборка Maven выполнена на Java 21.0.12.1
против `paper-api:1.21.11-R0.1-SNAPSHOT`.

## Выполнено

`mvn -o -B -Dmaven.repo.local=/workspace/.m2/repository -f gold/pom.xml package`
на Java 21 завершилась `BUILD SUCCESS`.
**48 тестов: 0 ошибок, 0 неудач, 0 пропусков.**

MockBukkit моделирует серверные события и предметы, а не реальную клиентскую
отрисовку. Для проверки свободного места использована тестовая модель полного
куба и воздуха: все формы ванильных блоков она не моделирует. В тестовом игроке
`saveData()` заменён фиксацией вызова, поскольку MockBukkit не записывает настоящий
`player.dat`. Рабочая версия вызывает реальный Paper API `Player.saveData()`
до очистки журнала восстановления.
Проверки запросов паков фиксируют вызовы `Player.addResourcePack`; реальная
загрузка файлов клиентом не имитируется.

## Проверки фонового сохранения в 1.0.2

Пять отдельных тестов исполнителя подтверждают выполнение I/O вне вызывающего
потока, вызов игровых callbacks только в main-thread drain, последовательность
критических записей, объединение контрольных снимков, защитное копирование данных,
отказ после ошибки и ограниченное ожидание на остановке.

Тесты событий проверяют 100 выгрузок посторонних чанков и 1000 пустых тиков без
новых записей, продолжение других задач во время заблокированного fsync, отсутствие
награды до подтверждения, отсутствие повторной награды от второго клика, отказ
экономики при ошибке диска, отмену смерти при изменённом инвентаре, отмену при выходе
и отсутствие повторного восстановления старого инвентаря по сохранённой квитанции.

Тестовые задержки управляются CountDownLatch и не зависят от скорости реального
диска. Ожидаемые SEVERE в тесте отказа диска — намеренно смоделированная ошибка;
в итоговых JUnit-отчётах ошибок/провалов нет.

## Проверка ресурс-пака

В 1.0.2 ресурсы не изменялись; используются прежние проверенные файлы РП.

- ZIP перечитан после записи, проверены CRC и отсутствие повторяющихся путей.
- JSON разобраны; проверены ссылки item_model → model → texture, родители моделей,
  PNG и OGG существующих ресурсов.
- Все **19** исходных файлов базы 1.05, кроме изменяемого `pack.mcmeta`, сохранены
  побайтно. Файлов `assets/smplore/` — **0**.
- У Golda одна замкнутая поверхность из **14** граней; каждое ребро исходной
  геометрии принадлежит двум граням. Проверены четыре ракурса экспортированной
  модели с реальным атласом и прозрачностью.
- Используется формат ресурсов Minecraft 1.21.11 (`75.0`) и система `items/*.json`,
  без старых `overrides` и без подмены стандартного `gold_ingot`.

Хеши и результаты: `Z_Gold-SHA256SUMS`, `Z_Gold-tests_1.0.2.json`,
`Z_Server_Pack_1.05_Gold.report.json`.

## Что не выполнялось

Настоящий Paper-сервер и Minecraft-клиент в этом окружении не запускались.
Официальные метаданные Paper 1.21.11 доступны, но скачивание серверного JAR
с `fill-data.papermc.io` заблокировано сетевым прокси (`403 Forbidden`).
Предварительный просмотр не выдаётся за игровую проверку. Производительность
под реальной многопользовательской нагрузкой не измерялась.

После установки на сервер следует пройти один полный цикл: принять общий пак,
выдать яйцо, дождаться подъёма, получить три партии золота, проверить оба ответа
на двух экземплярах и сравнить инвентарь/опыт до смерти и после respawn.
Также следует проверить совместную работу с установленными плагинами,
которые самостоятельно изменяют смерть или инвентарь.
